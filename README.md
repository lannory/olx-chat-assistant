# OLX-автовідповідач з мостом у Telegram

Сервіс стежить за чатами вашого акаунта OLX.ua через **OLX Partner API**, сам відповідає на типові питання покупців (наявність, Нова Пошта, самовивіз, стан/комплектація, торг), а все інше пересилає вам у Telegram. Відповісти покупцю можна прямо з Telegram.

- **Режим `draft`** (за замовчуванням): бот нічого не надсилає сам, лише пропонує чернетку з кнопками «Надіслати / Редагувати / Пропустити».
- **Режим `auto`**: шаблонні відповіді йдуть одразу, вам приходить копія. У тихі години відповіді відкладаються до ранку.
- **Торг** («торг є?», «скинете?», «за 7000 віддасте?», «остання ціна?», «крайня ціна?», «ціна на віддачу?») і **пропозиції ціни** просто числом («8000», «7500?», «6к?», «8500 беру», «5 відасте?», «пропоную 8000», пропозиція ціни через OLX) отримують відповідь «торг відсутній». Число до 100 вважається тисячами («7» = 7 000), якщо оголошення дорожче за 1 000 грн. Якщо запропонована сума не менша за ціну оголошення («9000 беру» на товар за 9 000), це не торг: бот пересилає повідомлення вам.
- **«Хочу замовити», «беру», «можна замовити?»** отримують прохання написати дані для відправки (`intents.order`). Якщо покупець замовляє через OLX Доставку, дані не потрібні, тому бот відповідає лише про доставку.
- **Дані для відправки** (ПІБ, телефон, відділення / поштомат / «НП 59») отримують «Дякую за замовлення!» (`intents.order_details`). Повідомлення з вимогою оплатити на картку («Карта банку…», «надішліть скріншот оплати») такої відповіді не отримують.
- **Подяки й підтвердження** («Добре, дякую», «Зрозумів», «🤝», «+») і **повідомлення про оплату** («Скинув», «Оплатив») пересилаються вам з позначкою, без автовідповіді й без LLM-чернетки. Якщо покупець згадує військову службу (ЗСУ, «я військовий», фронт, бригада тощо), відповідь інша: «На жаль, немає можливості зробити знижку.», а в картці Telegram з'являється позначка. Якщо оголошення на OLX позначене як «торг можливий», бот на торг не відповідає, а пересилає повідомлення вам.
- **Питання про ціну, обмін, вкладення й незрозумілі повідомлення** не отримують автовідповіді й завжди пересилаються вам.
- Бот **ніколи не починає діалог першим**, відповідає на одне питання в треді не більше одного разу й мовчить, якщо ви самі писали в треді за останні `OWNER_COOLDOWN_MIN` хвилин (відредагована через «Редагувати» чернетка теж вважається вашим повідомленням). Виняток — «Дякую за замовлення!» на дані для відправки: ця відповідь пропонується й одразу після вашого повідомлення.

## Як це працює

```
 OLX Partner API ──(кожні 90 с)──► Poller ──► дедуплікація (SQLite) ──► класифікатор (ключові слова)
        ▲                                                                   │
        │                                     ┌─────────────────────────────┼─────────────────────┐
        │                                     ▼                             ▼                     ▼
        │                             шаблонна відповідь           без автовідповіді      (опц.) LLM-чернетка
        │                     draft: чернетка │ auto: одразу /             │                 тільки draft
        │                            тихі години: відкласти               │                       │
        └──── POST /threads/{id}/messages ◄───┴──── Telegram: картка, кнопки, ForceReply ◄───────┘
```

- **Polling**: щоразу береться список тредів; повідомлення завантажуються лише для нових тредів, тредів зі зміненим `total_count` або з `unread_count > 0`. Тому нічого не загубиться, навіть якщо ви прочитали повідомлення з телефона.
- **Дедуплікація**: `uuid` кожного повідомлення зберігається в SQLite, тож після рестарту нічого не обробиться повторно.
- **Перший запуск** = базова синхронізація: вся наявна історія позначається обробленою, і бот не відповідає на старі розмови.
- **Ваші й ботові повідомлення**: усе, що сервіс надсилає сам, записується. Тому `sent`-повідомлення, які ви написали в додатку OLX, визначаються як ваші, і від них рахується пауза `OWNER_COOLDOWN_MIN`.

## 1. Реєстрація застосунку на developer.olx.ua

1. Відкрийте **https://developer.olx.ua** і увійдіть своїм акаунтом OLX.
2. Перед першим застосунком портал один раз попросить **Partner details**:
   - **Main purpose of the app**: `We are a sole user of our applications` (застосунок лише для вашого акаунта).
   - **Application owner** і **Phone number** — обов'язкові. Номер вводиться з кодом країни: замініть запропонований `+48` на `+380`.
   - **Company name**, **Tax ID**, **Website URL**, контактні email — необов'язкові. Приватній особі можна залишити порожніми; ФОП може вказати свої дані.
   - Унизу форми прочитайте й прийміть умови OLX API.
3. Натисніть **Add an app** і заповніть форму:
   - **App name** (обов'язково): будь-яка назва, напр. `Seller Assistant`. Слово «OLX» у назві краще не використовувати.
   - **App website URL**: необов'язково, можна залишити порожнім.
   - **Redirect URI**: адреса, на яку OLX поверне вас після входу (див. наступний розділ). Вимоги: **тільки HTTPS і не `localhost`**.
   - **App description** (обов'язково): що застосунок робить з API. Приклад наведено нижче.
4. Після **Add app** портал показує `client_id` і `client_secret`. Секрет зберігайте лише в `.env` і нікому не пересилайте.
5. Запишіть ключі в `.env` (`OLX_CLIENT_ID`, `OLX_CLIENT_SECRET`), а redirect URI — в `OLX_REDIRECT_URI`, **символ у символ** так, як зареєстрували.

Приклад опису:

> Personal assistant for my own OLX.ua seller account (used goods). It reads incoming messages in my chats, looks up my own adverts (title, price, description) for context, and sends replies to buyers in existing conversations — template answers to common questions or replies I write myself via Telegram. It marks threads as read. It never starts new conversations, never messages other users in bulk, and only accesses my own account.

> Ключі прив'язані до країни: застосунок з developer.olx.ua працює тільки з olx.ua. Тестового середовища OLX не надає, тому все працює з вашим реальним акаунтом. Тим більше варто почати з режиму `draft`.

## 2. Redirect URI: як отримати HTTPS

Після входу в OLX браузер повертається на `OLX_REDIRECT_URI?code=…&state=…`. Сервіс приймає цей запит на `/oauth/callback` і обмінює код на токени. Код діє **10 хвилин**. Є три варіанти, як це влаштувати.

| Варіант | Коли підходить | Redirect URI |
|---|---|---|
| **A. VPS + домен + Caddy** (рекомендовано) | Сервіс постійно працює на VPS | `https://bot.ваш-домен.ua/oauth/callback` |
| **B. Тунель** (cloudflared / ngrok зі сталим доменом) | Хочете запускати вдома | `https://<ваш-тунель>/oauth/callback` |
| **C. Вручну, без публічного сервера** | Немає домену й тунелю | будь-який HTTPS-URL, зареєстрований в OLX |

**Варіант C покроково:** зареєструйте в OLX будь-яку HTTPS-адресу, наприклад `https://example.com/olx-callback`, і вкажіть її ж в `OLX_REDIRECT_URI`. Після входу в OLX браузер перейде на неї (сторінка може показати помилку, це нормально). Скопіюйте **повну адресу з рядка браузера** й упродовж 10 хвилин надішліть боту: `/auth https://example.com/olx-callback?code=…&state=…`.

> Публічного ендпоінта «почати авторизацію» немає навмисно. Посилання для входу (з одноразовим `state`) бот надсилає лише вам у Telegram, тож ніхто інший не зможе підключити до бота свій акаунт OLX.

## 3. Telegram-бот

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєте токен і запишете його в `TELEGRAM_BOT_TOKEN`.
2. Дізнайтеся свій `chat_id`: напишіть [@userinfobot](https://t.me/userinfobot) або запустіть сервіс, напишіть своєму боту `/start` і знайдіть у логах рядок `ignoring update from a chat that is not allowed` з полем `chatId`.
3. Вкажіть його в `TELEGRAM_ALLOWED_CHAT_IDS`; кілька значень пишуться через кому. Усі інші чати бот мовчки ігнорує.

Бот працює через long polling, тому вхідний доступ ззовні для Telegram не потрібен.

## 4. Запуск локально

Потрібен **Node.js 22+** (цього вимагає SDK Gemini; розробка й тести велися на Node 24, Docker-образ використовує Node 22).

```bash
npm ci
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
# заповніть .env: OLX_*, TELEGRAM_*, для локального запуску NODE_ENV=development
npm run dev                 # tsx watch, кольорові логи
```

Production-збірка без Docker:

```bash
npm run build
npm start
```

`.env` підхоплюється автоматично з поточної теки.

## 5. Перша авторизація в OLX

1. Після старту бот надішле вам у Telegram «OLX: потрібна авторизація» з посиланням. Нове посилання можна отримати командою `/auth`.
2. Відкрийте посилання, увійдіть в OLX і дозвольте доступ.
3. Далі OLX перекине вас на redirect URI (варіанти A/B), і ви побачите сторінку «Готово ✅». Для варіанта C надішліть адресу боту через `/auth <адреса>`.
4. Бот напише «✅ OLX авторизовано» і проведе першу синхронізацію.

Токени зберігаються в SQLite й оновлюються автоматично. Access token оновлюється заздалегідь і при відповіді 401 (запит повторюється один раз). OLX видає новий refresh token при кожному оновленні, а невикористаний refresh token згорає через 30 днів, тому сервіс має працювати хоча б час від часу. Якщо оновити токен не вдалося, бот надішле алерт із посиланням на повторну авторизацію.

## 6. Запуск на VPS (Docker)

```bash
git clone <ваш-репозиторій> olx-bot && cd olx-bot
cp .env.example .env && nano .env      # ключі, токени, DOMAIN, OLX_REDIRECT_URI=https://$DOMAIN/oauth/callback

# Варіант A: з Caddy (автоматичний HTTPS від Let's Encrypt; DNS домену має вказувати на VPS, порти 80/443 відкриті)
docker compose --profile https up -d --build

# або тільки сервіс (якщо HTTPS робить ваш власний reverse proxy; застосунок слухає 127.0.0.1:3000)
docker compose up -d --build

docker compose logs -f olx-bot
```

- **Дані** (токени, оброблені повідомлення, чернетки) лежать у volume `olx-bot-data`. Бекап:
  `docker compose exec olx-bot node -e "require('better-sqlite3')('/app/data/olx-bot.db').backup('/app/data/backup.db')"`, потім `docker compose cp olx-bot:/app/data/backup.db ./`.
- **Шаблони** монтуються з `./config` тільки для читання. Редагуйте `config/*.json` на хості, зміни підхоплюються без перезапуску.
- **Оновлення**: `git pull && docker compose up -d --build`.
- **Healthcheck**: `GET /health` повертає `authorized`, `lastPollOkAt` і `pollStale`. Caddy назовні віддає тільки `/oauth/callback` і `/health`.
- **Зупинка** коректна: на SIGTERM сервіс чекає завершення поточного опитування й відправок.

## Шаблони й нотатки по оголошеннях

> **Ваші дані не потрапляють у git.** `config/templates.json` і `config/adverts.config.json` описують ваш бізнес (товари, умови, адресу, нотатки) і внесені в `.gitignore`. У репозиторії лежать лише нейтральні приклади `config/*.example.json` (вигаданий магазин ноутбуків). Перед першим запуском скопіюйте їх і заповніть своїми даними:
>
> ```powershell
> Copy-Item config/templates.example.json config/templates.json; Copy-Item config/adverts.config.example.json config/adverts.config.json
> ```

**`config/templates.json`** містить тексти автовідповідей. Плейсхолдери: `{item}`, `{title}`, `{price}`, `{url}`, `{payment}`, `{condition}`, `{kit}`, `{batteries}`, `{notes}`. Рядок, у якому всі плейсхолдери порожні, автоматично прибирається.

`{item}` — коротка назва товару замість повного заголовка («ноутбук», «зарядка», «зарядки»). Правила задаються в `items`: кожне має `match` (регулярний вираз для назви оголошення), `name`, необов'язкові `plural` / `plural_match` і `category`. Перемагає слово, що стоїть у назві першим, тож «Зарядка для ноутбука Lenovo» дає «зарядка», а «Ноутбук Lenovo + зарядка» — «ноутбук». `items.fallback` (напр. назви брендів) спрацьовує, лише якщо жодне правило не підійшло; інакше — `items.default` («товар»). Задати назву вручну можна полем `item` в `adverts.config.json`.

- `pickup_words` — ваші слова, що означають самовивіз (назва району тощо), як регулярні вирази.
- `llm.seller_context` — що LLM має знати про вас: товари, місто/район, умови доставки й оплати. Підставляється в підказку Gemini; у коді цих даних немає.

- `intents.availability | delivery | pickup | condition | bargain | order | order_details` — шаблони для семи типів повідомлень. Якщо в одному повідомленні кілька питань, вони об'єднуються в одну відповідь з одним `greeting`, напр. «Добрий день! Так, … ще в наявності. Торг відсутній.». `greeting` додається лише до першої відповіді в треді: якщо продавець уже писав або чернетка вже чекає на відправку, наступні відповіді починаються одразу по суті.
- `greeting_evening` і `evening_hours` — вечірнє привітання: з `from`:00 до `to`:00 за `TIMEZONE` (за замовчуванням 18:00–06:00) бот пише `greeting_evening` («Добрий вечір!»), решту часу — `greeting` («Добрий день!»). Час береться на момент відповіді; якщо в режимі `auto` відповідь відкладено до кінця тихих годин, привітання підбирається під час відправки. LLM-чернетки вітаються так само.
- `intents.bargain_military` — відповідь на торг, коли покупець згадує військову службу. Ознака шукається в останніх повідомленнях покупця в треді, тож «я з ЗСУ» і «знижка буде?» можуть прийти окремими повідомленнями.
- `shipping` — відповіді на питання про доставку для кожної категорії товару (назви категорій довільні, напр. `main` і `accessory`). У кожному наборі: `general` (загальне питання або кілька способів одразу, напр. «наложкою чи OLX?»), `olx` (питають про OLX Доставку), `cod` (про накладений платіж), `ukrposhta` (про Укрпошту). Категорія береться з правила `items`, що спрацювало. Задати вручну можна полем `category` в `adverts.config.json`. Якщо тип не визначено, бот не вгадує умови: питання пересилається вам (або йде в LLM-чернетку).
- `{olx_price}` — ціна з комісією OLX Доставки, бот рахує її сам: ціна + `olx_fee.percent`% + `olx_fee.fixed` грн, округлення вгору до `olx_fee.round_to` грн (за замовчуванням 3% + 20 грн, до 10 грн; 9 000 → 9 290 грн).
- `payment` — використовується лише без секції `shipping`: текст для `{payment}` у `intents.delivery`, варіант за `SHIPPING_COD` і `SHIPPING_PREPAY` у `.env`.
- `quick` — швидкі шаблони для кнопки «📋 Шаблони» в Telegram.
- `photos` — набори фото, які бот може надіслати покупцю. Кожен набір: `id`, `label` (текст кнопки), `text` (повідомлення разом із фото), `urls` (1–10 посилань), необов'язкові `adverts` (ID оголошень; порожньо — для всіх) і `match` (регулярний вираз — слова покупця, що означають цей набір, напр. `велик\\p{L}*\\s+(комплект|набір)`).
  - **Вручну:** кнопка «📷 Фото» під карткою треду → оберіть набір → бот надсилає текст і фото.
  - **Автоматично:** на «скиньте фото…», «а фото є?», «можна фото комплекту?» або на слова з `match` бот пропонує чернетку з фото. Набір обирається, лише якщо зрозуміло, про який ідеться: покупець ужив слова з `match`, або для цього оголошення є один набір без `match`. На «фото серійника» чи «фото з лінійкою» бот фото не вгадує — натисніть «📷 Фото» або відповідайте вручну.
  - **Обмеження OLX API:** фото передаються лише посиланнями (`attachments: [{ url }]`), завантажити файл напряму API не дозволяє. Посилання мають бути публічними й вести прямо на зображення (`.jpg`/`.png`). Як OLX показує такі вкладення покупцю, документація не описує — перевірте на тестовому чаті.

**`config/adverts.config.json`** містить нотатки по кожному оголошенню, ключ — `advert_id`:

```json
{
  "adverts": {
```

`advert_id` — це числовий ID оголошення. Його видно в картці в Telegram (якщо назва недоступна) і в API. Для питань про стан і комплектацію **автовідповідь іде лише за наявності нотаток** для цього оголошення. Без нотаток повідомлення просто пересилається вам.

Якщо JSON-файл після редагування зламаний, сервіс залишає попередню робочу версію й пише помилку в лог.

## Команди й кнопки Telegram

| Команда | Що робить |
|---|---|
| `/status` | Режим, пауза, час останнього успішного опитування, непрочитані треди, чернетки, стан авторизації |
| `/mode draft` / `/mode auto` | Перемикає режим (зберігається в БД і має пріоритет над `MODE` з `.env`) |
| `/pause` / `/resume` | Пауза: OLX не опитується, нічого не надсилається |
| `/templates` | Показує поточні шаблони |
| `/auth` | Надсилає посилання для (повторної) авторизації в OLX |
| `/auth <адреса>` | Ручне завершення авторизації (варіант C) |

**Картка треду** містить оголошення з ціною й посиланням, ім'я покупця, останні 3–5 повідомлень (👤 покупець, 🧑 ви, 🤖 бот) і статус. Під нею кнопки:

- ✅ **Надіслати** / ✏️ **Редагувати** / ⏭ **Пропустити** — дії з чернеткою. Подвійне натискання не відправить її двічі.
- 💬 **Відповісти** — бот попросить текст (ForceReply), і ваша відповідь піде в цей тред OLX. Так само можна просто зробити reply на картку.
- 📋 **Шаблони** — швидкі відповіді з `quick`.
- 👁 **Прочитано** — `mark-as-read` в OLX.
- 🔕 **Ігнорувати тред** — більше не пересилати цей тред; дію можна скасувати.

Коли ви відповідаєте самі, бот закриває відкриті чернетки цього треду й запускає паузу автовідповідей.

## Налаштування `.env`

Повний список з коментарями — у [`.env.example`](.env.example). Основне:

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `POLL_INTERVAL_SEC` | `90` | Інтервал опитування (мін. 30) |
| `MODE` | `draft` | `draft` або `auto` |
| `OWNER_COOLDOWN_MIN` | `30` | Пауза автовідповідей після вашого повідомлення в треді |
| `QUIET_HOURS` | — | Напр. `23-8`; порожньо = вимкнено |
| `TIMEZONE` | `Europe/Kyiv` | Для тихих годин і часу в картках |
| `SHIPPING_COD` / `SHIPPING_PREPAY` | `true` | Накладений платіж / передоплата в шаблоні НП |
| `LLM_ENABLED` | `false` | LLM-чернетки через Google Gemini (потрібен `GEMINI_API_KEY`) |
| `LLM_MODEL` | `gemini-3.5-flash-lite` | Модель Gemini (див. нижче) |

**LLM-чернетки** (опціонально): у режимі `draft` для повідомлень без шаблонної відповіді бот попросить Gemini скласти чернетку на основі оголошення (назва, ціна, опис), нотаток і історії треду. Те саме для питань про стан і комплектацію, коли для оголошення немає нотаток в `adverts.config.json`: Gemini складає всю відповідь за описом оголошення (якщо він не відповів, лишається шаблонна чернетка без частини про стан). Такі чернетки **ніколи не надсилаються автоматично**, лише після вашого «Надіслати». Промпт забороняє обіцяти знижки й називати точну адресу.

Модель за замовчуванням, **`gemini-3.5-flash-lite`**, безкоштовна на free tier Gemini API. Як отримати ключ:

1. Увійдіть у Google-акаунт на **https://aistudio.google.com/apikey**.
2. Натисніть **Create API key**. Картка не потрібна.
3. Впишіть ключ у `.env`: `GEMINI_API_KEY=...` і `LLM_ENABLED=true`.

Що варто знати про free tier:

- **Ваші дані.** За умовами Gemini API для безкоштовних сервісів Google може використовувати запити й відповіді для покращення своїх продуктів, а люди-рецензенти можуть їх читати. Тому бот **не передає ім'я покупця**, а телефони, email, номери карток і `@нікнейми` замінює на `[номер]`, `[email]`, `[нік]` перед відправкою. Решту тексту листування Google все одно бачить; якщо це неприйнятно, тримайте `LLM_ENABLED=false`.
- **Ліміти.** Free tier має обмеження на кількість запитів за хвилину й за добу; поточні цифри видно в AI Studio. Якщо ліміт вичерпано (HTTP 429), бот просто перешле повідомлення без чернетки, а на наступних повідомленнях спробує знову.
- **Відповідність умовам.** Умови дозволяють безкоштовний рівень для професійного й ділового використання, а не для споживчого, і забороняють надавати через нього застосунки користувачам з ЄЕЗ, Швейцарії та Великої Британії. Бот працює лише для вас в Україні, тож ці обмеження його не зачіпають.
- **Інші моделі.** Якщо `gemini-3.5-flash-lite` стане недоступною, задайте іншу безкоштовну модель зі списку на https://aistudio.google.com/docs/models в `LLM_MODEL`.

## Особливості OLX API, які варто знати

Під час розробки код звірено з офіційною специфікацією `developer.olx.ua/swagger/v2/partner_api.yaml` і гайдами developer.olx.ua. Ось що з неї випливає:

- **ID**: числові `id` тредів і повідомлень позначені як deprecated, тому сервіс використовує `uuid` / `thread_uuid`.
- **Ліміт запитів**: 4500 запитів за 5 хвилин з одного IP. Після перевищення CloudFront блокує IP **на 30 хвилин** і віддає HTML 403, а не JSON 429. Сервіс розпізнає це, ставить опитування на паузу й надсилає алерт. Для 429/5xx працює експоненційний backoff з jitter; `Retry-After` враховується, якщо OLX його надішле (у документації заголовок не описано).
- **Час**: `created_at` приходить як `"YYYY-MM-DD HH:mm:ss"` без часової зони. Сервіс трактує його як київський час. Нові повідомлення визначаються за `uuid`, а не за часом.
- **Ім'я покупця** береться з `GET /users/{interlocutor_id}`, бо в треді його немає.
- **Команди треду**: існують лише `mark-as-read` і `set-favourite`. «Ігнорувати тред» зберігається тільки локально.
- **Формат відповідей** у документації непослідовний: `/threads` описано як масив, а `/adverts/{id}` як `{data: …}`. Клієнт приймає обидва варіанти.
- **`Content-Type` у GET-запиті** призводить до відповіді 400, тому заголовок надсилається лише з тілом запиту.
- **Вебхуків для повідомлень немає**, тож polling — єдиний варіант.

## Розробка

```bash
npm run check      # tsc --noEmit + eslint + vitest
npm test           # лише тести
```

Структура:

```
src/
  config.ts            zod-валідація .env
  worker.ts            точка входу, зв'язування, graceful shutdown, алерти
  server.ts            Fastify: /oauth/callback, /health
  olx/                 OAuth, HTTP (retry/backoff/401-refresh), типізований olxClient, zod-схеми
  poller/              опитування й дедуплікація (poller.ts), рішення по треду (processor.ts)
  rules/               класифікатор, шаблони, політика (cooldown, «один раз на питання»)
  services/            контекст треду, відправка в OLX, життєвий цикл чернеток
  telegram/            grammY-бот і форматування карток
  llm/                 опціональні чернетки через Google Gemini
  db/                  ЄДИНИЙ модуль із SQL (better-sqlite3) + міграції
tests/                 vitest, моки fetch і Telegram API, без реальних запитів
```

**Перехід на PostgreSQL**: увесь SQL зібраний у `src/db/index.ts` (клас `Db`) і `src/db/migrations.ts`. Достатньо переписати цей клас на `pg` з тими самими методами (асинхронними) і поправити `await` у місцях виклику. Схема використовує ANSI-типи (`BIGINT`, `TEXT`, `DOUBLE PRECISION`), а час зберігається як epoch у мілісекундах.
